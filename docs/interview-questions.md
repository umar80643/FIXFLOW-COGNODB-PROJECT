# Interview prep

1. Why did you choose a graph database for this use case?
2. What makes the `Device -> Symptom -> Cause -> Guide -> Part -> Tool` path useful?
3. How did you design the labels and relationship types?
4. Why is the seed data realistic?
5. How does the app behave when the database is offline?
6. Which queries would be awkward in a relational model?
7. How do you keep the Cypher parameterized?
8. What would you index first in production?
9. How would you extend the schema for user repair history?
10. How would you add recommendation ranking?
11. What is the difference between a symptom and a cause in this model?
12. How would you support image-based repair diagnostics?
13. How would you add multi-language support?
14. How would you model spare parts inventory?
15. What would you cache at the API layer?
16. How would you support venue geolocation?
17. How would you validate imported seed data?
18. How would you test the Cypher queries?
19. What does graceful degradation look like in your backend?
20. How would you deploy the frontend and backend separately?
